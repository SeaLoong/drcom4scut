# 无线网页登录

[返回首页](../README.md)

**校园无线网通常需要先连 Wi-Fi，再在学校网页中输入账号密码。** 本项目的无线模式尝试把兼容页面的登录操作交给程序完成，并定期检查是否还在线。

它不会连接 Wi-Fi、选择无线网络或替系统取得 IP 地址；这些仍在电脑或路由器的网络设置中完成。也不需要安装 Npcap 或配置有线网卡抓包权限。

## 先确认自己的网页登录方式

1. 在系统网络设置中连接校园 Wi-Fi。
2. 打开浏览器，进入学校提供的登录页面，确认自己能手动输入账号密码登录。
3. 记下未填写账号密码时的登录页地址。不要复制含密码、登录令牌或个人会话信息的链接。

如果浏览器登录已经满足需要，可以继续使用网页，不必安装本程序的无线模式。

目前自动登录只实现特定的 **DrCOM/ePortal 账号密码页面**。这类页面背后的网络请求已有公开客户端参考，但本项目还没有在华工校园实网完成验证。需要验证码、短信、扫码、统一身份登录，或使用其他系统的页面不在当前支持范围。

## 用图形界面尝试

普通电脑用户推荐 [drcom4scutGUI](https://github.com/SeaLoong/drcom4scutGUI#readme)：选择“无线 Portal”（即无线网页登录），填写校园账号、密码和刚确认的学校登录页地址，再点击“认证”。

高级选项里的 API、AC IPv4 和载荷 IPv4 通常先留空。不要把其他人的地址照搬过来，也不要为了消除报错猜测端口或学校地址。自动登录不兼容时，仍可以回到浏览器登录。

## 配置

下面是给命令行用户的最小示例。把 `base_url` 的占位内容替换为**你自己核对过的学校登录页地址**，不要原样运行：

```yaml
mode: portal
username: '你的校园网账号'
password_file: password
portal:
  base_url: '在这里填写实际的学校登录页地址'
  allow_http: false
```

将文件保存为 `portal.yml`，在同目录创建只含一行密码的 `password` 文件。Mac / Linux 执行 `chmod 600 password`，完整说明见[密码与路径](configuration.md#密码与路径)。

程序模板中保留的 `s.scut.edu.cn` 是默认主机名，**不能据此认定它就是你所在校区当前的无线入口**。学校可能使用其他入口；以浏览器实际页面和学校说明为准。

### 高级字段什么时候需要填？

只有已经从学校页面、网络管理员或可核查资料中确认值时，才填写这些字段：

| 字段 | 简单理解 | 何时填写 |
| --- | --- | --- |
| `portal.base_url` | 浏览器登录页的入口地址 | 必填自己确认的入口；可以保留学校提供的公开接入点参数 |
| `portal.api_url` | 页面背后提交认证请求的地址 | 学校使用的接口与程序默认推导不同时 |
| `portal.ac_ip` | 学校侧接入控制设备的地址 | 程序无法从可信入口找到它时 |
| `portal.client_ip` | 学校登录系统看到的这台设备地址 | 学校没有自动报告它时 |
| 顶层 `ip` | 这台电脑实际已取得的本地地址 | 多网卡时需要固定请求从哪一个本地地址发出 |
| 顶层 `mac` | 设备网卡的硬件地址 | 已知该值，且需要进一步核对在线设备时 |

`api_url` 省略时，当前实现会在同一主机上尝试 HTTPS 的 802 端口或 HTTP 的 801 端口。这是兼容特定 DrCOM 系统的默认规则，不是从任意网页登录页都能推导出的规则；不匹配时请核对学校实际接口，而不是反复猜测。

页面入口与认证接口必须使用同一主机。程序不会把密码跟随跳转发送给其他主机；如果学校确实改用了另一入口，先核实再修改配置。部分网络经过路由器转发，学校看到的设备地址可能与电脑本地地址不同，因此上述两个 IP 字段不能简单互换。

## 启动、查看状态和退出

先检查配置，再开始认证：

```sh
./drcom4scut --config portal.yml --check-config
./drcom4scut --config portal.yml --status-file portal-status.json
```

在另一个终端查看：

```sh
./drcom4scut status --status-file portal-status.json
```

只有学校系统确认当前设备在线，程序才把状态设为 `online`。仅收到“登录请求已接受”或网页返回成功，并不足以说明认证完成。无线模式不执行有线认证，所以状态中的 `eap_authenticated` 为 `false` 是正常的。

如果学校明确报告这台设备已由另一账号登录，程序会提示，不会自动踢掉对方。需要换号时，先用学校网页退出原账号，再重新认证。学校不返回账号归属时，程序只能确认设备在线，不能额外证明它属于哪个账号。

按 **Ctrl-C** 停止，程序会尝试向门户注销。也可以单独请求退出当前门户会话：

```sh
./drcom4scut --config portal.yml --logoff
```

该命令不读取账号密码，但仍需正确的登录入口和设备信息。它请求退出会话，不会清除学校网页中的“记住我”、自动登录或设备绑定设置；若很快又被网页自动登录，请在学校页面关闭相应设置。不能将此操作理解为所有门户都支持的“解绑设备”。

## 使用 HTTP 门户

优先使用学校提供的 **HTTPS** 地址，它会加密账号密码的网络传输。地址以 `http://` 开头时，这段传输没有 HTTPS 的保护。

只有确认学校当前只提供 HTTP，并愿意使用这种传输方式时，才把 `portal.allow_http` 改为 `true`；图形界面中对应“允许 HTTP”。不要仅因为 HTTPS 登录失败就自行换成 HTTP。程序也不会自动降级。

Windows、macOS 和 GNU Linux 默认包支持 HTTPS，并正常检查网站证书。当前 OpenWrt 静态包只支持明确允许的 HTTP 网页登录；遇到 HTTPS 入口时不能用关闭证书检查解决，需要另行构建支持 HTTPS 的程序，见[开发说明](development.md#构建特性)。

## 常见问题

| 提示或情况 | 可以怎样处理 |
| --- | --- |
| 连接 Wi-Fi 后没有登录页 | 先通过浏览器打开学校官方入口，确认无线连接和学校当前要求；客户端不会代替系统选择 Wi-Fi |
| 页面有验证码、短信或扫码 | 当前自动登录不支持，请继续用学校网页 |
| `HTTP portal requires explicit...` | 当前地址使用 HTTP；核对学校地址后，再决定是否明确允许 |
| `HTTPS portal requires...portal-tls` | 当前程序不支持 HTTPS，换用支持它的包或按开发说明构建 |
| `Portal AC address was not discovered` | 程序没找到学校接入设备地址，先核对入口；有学校提供的值时再填 `portal.ac_ip` |
| `Portal did not report a usable client IPv4` | 学校没有报告当前设备地址，检查无线连接和入口；确认实际值后再填 `portal.client_ip` |
| `Portal redirect was rejected` | 页面跳到了另一主机；核实学校当前入口后修改，不要把密码转发到未知地址 |
| `accepted login but did not confirm...` | 请求被接受但未确认设备在线；先试浏览器登录，再检查完整账号、设备地址及页面是否兼容 |
| 停止后又自动上线 | 在学校网页检查自动登录、记住账号和设备绑定设置 |

账号会按填写内容原样发送；学校要求运营商后缀时，也需要填写完整。反馈时提供程序版本、网页登录方式和已遮住个人信息的错误提示即可，不要公开登录请求、密码或服务器原始回显。

## 自动登录方案从哪里来？

实现参考了 [SCUTNetLogin 的无线认证代码](https://github.com/YiZhiQvQ/SCUTNetLogin/blob/65470c3da502527fa5f20673d71639c8bebb9747/src/wifi/webauth_process.cpp)和 [OpenWrt 自动登录脚本](https://github.com/Breeze1733/luci-app-scut-autologin/blob/0143bb299dc35642ab54025c55bdbfbc4460a01f/root/usr/lib/scut-autologin/login.sh)记录的页面请求流程：查设备状态、提交账号密码、确认在线、请求注销。

这是对网页登录请求的独立实现，不是用浏览器自动点击按钮，也不是重新发明一种无线连接方式。现有自动测试使用本机模拟网页服务器，只能检查请求和处理逻辑；不能据此保证当前校区的网页登录一定可用。详细来源保留在[相关客户端记录](references-clients.md)，开发测试范围见[开发与验证](development.md#测试层次)。
