# 连接与排障

[返回首页](../README.md)

遇到连接问题，按 **系统网络 → 环境自检 → 账号设置 → 连接状态** 的顺序检查，通常能快速找到原因。

## 先看这四项

1. **系统网络已连接。** 有线时确认网线插好、以太网已经取得地址；无线时先在系统设置里连上校园 Wi-Fi。
2. **选择了正确的网卡。** 有线认证选择连接学校网线的以太网网卡；同时开着 Wi-Fi、VPN 或多个 USB 网卡时尤其值得核对。
3. **环境自检通过。** GUI 点击“环境自检”；终端执行 `./drcom4scut doctor --interface 你的网卡名称`。
4. **账号填写完整。** 使用学校提供的校园网账号和密码；需要运营商后缀的账号，连同后缀一起填写。

## 按遇到的情况处理

| 情况 | 建议操作 |
| --- | --- |
| 程序打不开、提示格式错误 | 按[下载对照表](download.md)选择正确的系统和处理器，重新解压完整压缩包 |
| GUI 提示找不到核心 | 将核心放在 GUI 程序旁边；Mac 放在 `.app` 旁边。见[安装说明](https://github.com/SeaLoong/drcom4scutGUI#安装) |
| Windows 有线自检提示缺少驱动 | 安装 [Npcap](https://npcap.com/#download)，然后重新运行自检 |
| Mac / Linux 自检提示权限不足 | 按 [Mac](macos.md#有线抓包权限) 或 [Linux](https://github.com/SeaLoong/drcom4scutGUI/blob/master/docs/usage.md#linux) 的首次网卡授权步骤处理 |
| 密码文件找不到 | 核对配置中的文件名与实际文件名，特别是 Windows 自动补上的 `.txt`；配置中的相对路径从配置文件目录开始查找 |
| 密码文件权限提示 | Mac / Linux 将文件设为当前用户所有并执行 `chmod 600 password`；后台服务按对应安装指南设置 |
| 程序正在运行，但尚未显示在线 | 观察最后一条错误提示；完整有线认证要等后续会话建立成功。先用默认设置排查 |
| 休眠、拔线后暂时离线 | 等系统恢复网卡和地址，再观察客户端的重连状态；需要立即重试时先断开，再连接 |
| 无线网页登录失败 | 在浏览器打开学校登录页验证账号与入口，再按[校园网页登录指南](portal.md#常见问题)核对 |
| 认证显示在线，某个网站打不开 | 同时试其他网站，并检查系统 DNS、VPN 和代理设置，区分认证状态与网站访问问题 |

## 连接经常中断

新版本会重试丢失的保持连接请求；持续收不到回复时，会尝试重新建立后续会话。可以先检查网线接触、系统休眠、电源管理，以及故障是否只在同时连接 Wi-Fi 或开启 VPN 时出现。

保留故障前后几分钟的日志与发生时间，能帮助判断是网络变化、学校服务器暂时没有回复，还是账号提示。需要临时增加日志内容时，把配置中的 `log.level` 改为 `DEBUG`，重新连接并复现一次，随后恢复 `INFO`。

GUI 可查看窗口中的日志；终端使用 `./drcom4scut logs --config config.yml`；OpenWrt 使用 `logread -e drcom4scut`。各自的安装指南也说明了日志保存位置。

## 怎样提交有效的问题反馈？

在[核心问题反馈](https://github.com/SeaLoong/drcom4scut/issues)或[图形界面问题反馈](https://github.com/SeaLoong/drcom4scutGUI/issues)中写明：

- 系统和客户端版本；路由器另外附型号与固件版本。
- 有线连接还是校园网页登录，故障前后做了什么。
- 看到的完整错误提示，以及自检结果。
- 是否同时使用 Wi-Fi、VPN 或多张网卡，是否在休眠、拔线后发生。

分享前遮住账号、密码和个人网络信息，保留错误文字和事件时间即可。校园实网的反馈能帮助进一步确认兼容性；现有自动测试主要覆盖程序逻辑与各平台运行行为。
